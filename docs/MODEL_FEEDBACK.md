# 局内模型反馈与旁路评测

Link 3.4.0 新增 WebUI「模型反馈」。它复用当前对局已加载的 V4 模型，以服务器实际接收者的玩家可见信息评测场面；本批尚不接入服务器观众席

## 如何使用

重启 Link 服务进程并刷新 WebUI，进入「模型反馈」

- **读取模型反馈**默认开启，在 Core-only、hybrid、LLM review 的正常 Core 决策中共用同一次前向，不为面板额外运行一遍模型
- **持续旁路评测**默认关闭，开启后可以在对手回合或纯 LLM 模式独立评测场面，需要先加载可用的 V4 模型
- 两个开关均可在会话未启动时保存，通过统一控制接口持久化；关闭反馈不改变决策模式，也不删除已取得的历史
- 页面展示采样曲线、胜／平／负预测、折扣价值、预计剩余事件和本次动作分布。曲线最多保留 128 点，停止对局后保留最近一局的缓存，新局开始后清空

真实后端能力决定显示哪些指标。未提供的结果显示为空，不补零、不用前后时点或另一名玩家的预测填空，也不把本方预测的补数当成对手独立预测

## 预测输出含义

| 指标 | 来源与含义 |
| --- | --- |
| 胜／平／负概率 | V4 目标规划解码器的状态级 `terminal_outcome_logits`，按 loss、draw、win 顺序 softmax |
| 预计剩余事件 | 状态级 `terminal_remaining` 的归一化对数长度，按 V4 的 `log1p(1500)` 合同还原，单位是动作转移事件，不是回合 |
| 折扣价值 | 原模型 `values` 输出，受到训练奖励、折扣和策略分布影响，可超出负一到一，不换算成胜率 |
| 动作置信度与分布 | 当前合法候选上的策略概率，保留所选温度和拒绝候选过滤的实际含义，不表示对局胜率 |

终局输出来自已存在的模型参数，不证明其已充分训练或在线校准。初期权重可能给出接近均匀的概率；当前 UI 与 API 标为 `uncalibrated`。Link 的 V4 在线历史仍使用 `masked_unavailable`，动态字段覆盖也可能不完整

本批不启用逐动作训练辅助头，不推演未来操作，不生成模型未提供的效果解释，也不修改实际动作选择

## PTH 与 ONNX

PTH 通过 V4 已有的 `return_evaluation=True` 和 `evaluate_state()` 读取状态级终局头，使用同一主干和原权重，不改变模型协议、网络结构或输入张量

当前 Core 的普通 ONNX 导出只有 `action_logits`、`values`。此类图可以正常显示价值及实际决策分布，胜／平／负和剩余事件保持为空。Link 不要求为继续对局重导出，也不会因为缺少可选预测头拒绝加载

若图实际导出了 `terminal_outcome_logits`、`terminal_remaining`，Link 可以从同一次 ORT 调用中取得这些可选输出。当前已用受控四输出图验证这一读取合同，尚不声称 Core 已提供该导出。可交给 Core 维护方的可选增强说明见 [ONNX 终局输出建议](CORE_ONNX_EVALUATION_EXPORT.md)

## 异步与时点

持续采样每轮至少间隔 0.75 秒，合并连续服务器刷新，不保证每个事件都有预测。后台读取独立快照，仍绑定实际接收者，菜单清空后执行状态评测，不虚构动作

旁路与主决策串行使用原模型线程池。主提示到来时取消旁路调度并优先处理实际操作；已经启动的模型线程不能被 Python 强制中止，仍占用模型时主操作直接走现有回退，不往同一线程池继续排队。旁路最多等待两秒或当前更短的 Core 预算，等待超时后保留占用标记直到线程真正结束，不熔断整局 Core

结果返回时再次核对状态序号和代次，场面已更新、重建、新局或关闭产生的过期结果不发布。Type162 重建取消旧评测；已完成历史仍是真实采样，不被改写成新状态

正常决策复用的预测与该决策快照绑定。当前状态已变化时，页面明确显示「最近采样 · 场面已更新」；记录不会延长成未来时点的预测

## 共享接口

`GET /api/v1/model-feedback` 沿用访问令牌鉴权，只读取缓存，不加载模型或触发推理。返回 `galatea.model_feedback.v1`：

- `enabled`／`passive_enabled`：人工控制开关
- `available`／`current`／`scope`：有无采样、是否对应当前状态、当前局或上局记录
- `latest`：最近预测，带实际视角、状态序号、请求编号、回合、阶段、时间和公开模型身份
- `history`：最近最多 128 点；不含卡片输入、完整报文、用户聊天或密钥
- `last_error`：简短原因，不含模型输入或底层请求内容

运行状态提供不带整条曲线的 `runtime.model_feedback` 摘要，新点发布 `model.feedback.updated` 事件。AstrBot／dsh 可以复用缓存接口；新增专用插件工具时仍须沿用原来的会话所有者检查

原有 `include_core_suggestion` 开启时，送往 LLM 的同次 Core 建议增加 `state_evaluation`，只包含小型预测结果，不重复发送整条曲线。关闭该建议开关仍不注入 Core 建议；纯旁路结果通过共享接口读取，不自动把旧预测作为当前决策答案

设置仍使用 `PATCH /api/v1/controls` 的 `intervention` 分区，保留 revision 检查：

```json
{
  "patch": {
    "intervention": {
      "core_feedback_enabled": true,
      "core_feedback_passive_enabled": true
    }
  },
  "expected_revision": 0
}
```

配置文件使用 `decision.core_feedback_enabled` 和 `decision.core_feedback_passive_enabled`。API v1、已有决策身份及插件模式不变；旧插件可继续使用，同次预测字段会随原观察传入主智能体

## 验证与现场复核

`tests/test_model_feedback.py` 覆盖真实 PTH／双输出 ONNX、受控四输出 ONNX、无候选和对手回合评测、玩家视角隔离、同次前向计数、非有限输出、历史上限、旁路超时占用与迟到结果、接口鉴权及离线持久开关。浏览器已检查浅色／深色、真实缓存接口、空概率降级和设置保存

现场复核可按以下三项集中进行：正常 V4 对局打开面板看新点持续出现；开启旁路后在对手回合观察采样及操作响应；停止再开新局，确认上局缓存与新局清理。使用目前的双输出 ONNX 时，概率为空是输出能力边界，价值仍应正常更新。实际预测质量和长局性能仍需生产权重检验，观众席单独推进
