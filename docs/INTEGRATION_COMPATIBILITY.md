# Link 与 AstrBot／dsh 的升级兼容和后续方案

核对日期：2026-11-05，Link 3.3.16。本次只读核对工作区的 AstrBot 插件 1.9.2 和 dsh 插件 0.1.1，没有修改或发布两个插件仓库；这里的版本不表示已经核对上游最新发布

## 当前是否需要同步升级

**最近的 V4 模型推理、Type16／31 修复以及 Type162 场面重建，只升级并重启 Link 即可，不要求 AstrBot 和 dsh 插件同步更新**

三个版本各自独立：Link 软件版本、Core 模型协议 V3／V4、外部 `galatea.link.api.v1`。插件只使用 Link 的 HTTP／WebSocket，不解析游戏二进制，也不加载 PTH、ONNX 或模型词表

本地 AstrBot 的远程决策准备流程复制完整观察，只移除已由聊天处理器消费的聊天正文。dsh 同样将观察复制后序列化，合法动作仍按 `choice_id` 提交。新增的强制标志、公开通知、重建来源和缺口说明因此能进入主智能体输入，不需要插件逐字段改造

兼容前提是已具备远程决策桥接、请求过期处理和会话隔离的插件版本。不能把上述结论扩展为任意历史版本都支持；实际安装了更老的插件时，应先对齐对应插件仓库已发布的桥接版本

| Link 更新内容 | 现有插件是否必须同步升级 | 说明 |
| --- | --- | --- |
| V4 PTH／ONNX 推理、温度、重复回退 | 否 | 留在 Link 内部，现有模式和动作提交接口不变 |
| 游戏报文解析、查询缓存、场面重建 | 否 | 插件获得修正后的标准 JSON 观察 |
| 在观察和状态中增加可选信息 | 否 | 现有客户端透传观察；旧界面可以暂不展示新字段 |
| 模型导入、GKG 卡组入库的插件工具或面板 | 使用这些新入口时需要 | 当前可先通过 Link WebUI 完成，已有对局能力不受影响 |
| 真实观众席与异步场面评测 | 使用这些新能力时需要 | Link 需先实现独立模式、权限与事件，插件再增加相应工具 |
| BO3 换备 | 将来使用时需要 | 当前尚未接通，不把赛前编辑 side 区当作换备 |
| 删除或改变必填字段、请求身份、权限含义 | 是 | 必须另行设计迁移，不能在 API v1 内静默破坏 |

`GET /api/v1/capabilities` 的可选 `online_observation` 从 3.3.16 声明玩家视角 Type162 重建；`field_reload_card_identity=false` 表示这条快照本身没有场上卡片身份，仍需后续查询。`spectator_seat=false` 和 V4 的 `spectator_evaluation=false` 继续明确尚无观战功能

3.4.0 新增 [局内模型反馈](MODEL_FEEDBACK.md)，共享接口与开关继续是 API v1 的可选增强。已有 Core 建议会携带同次小型预测，插件透传即可，无需为继续对局强制升级；插件若要提供独立读曲线或旁路设置工具，再增加相应调用和所有者检查。服务器观众席仍未接通，当前玩家局内旁路不改变该边界

## 后续第一批：插件信息与能力识别维护

这是建议的维护批次，尚未在插件仓库实施，不是当前开局的强制前置条件

1. 两端状态同时显示 Link 软件版本、API 版本、所选模型协议、推理后端和能力状态，不把 Core 框架软件版本当作模型协议
2. AstrBot 清理模型列表、工具帮助和面板中的 V3 专用文案。当前插件元数据为 1.9.2，但心跳仍报告 1.9.1，应改成统一版本来源
3. dsh 的环境自检改用 `model_protocol_version`、模型实际就绪信息与 `semantic_maintenance_supported`。不能给 V4 缺资产提示“补齐 V3 资产”，也不能建议调用明确只支持 V3 的维护器
4. dsh 在纯 LLM 模式下不应因为没有选择 Core 模型就一律判定无法开局；Core 模式需要的模型／资产条件仍由 Link 提供实际错误原因
5. 两端区分“API 不兼容”和“缺少某项可选能力”。未知可选字段不报错，新工具发现能力缺失时给出说明；V4 标为 preview 不等于禁止已开放的兼容在线推理
6. 连接页面提供运行中的 Link 版本核验，说明更新后需要重启服务进程；WebUI 停止游戏会话不等于重启服务

建议分别作为插件的小版本维护发布，不捆绑 Link 的每次解析补丁。验证包括旧／新 Link 响应、多余可选字段、原有会话隔离、过期请求取消及不强制覆盖决策模式

## 后续第二批：新增管理入口

Link 的管理能力先完成，再在插件中按需求开放，保持所有推理和资产处理在 Link

- 模型仓库：展示 V3／V4、PTH／ONNX、资产状态与加载警告，允许按明确标识选择下次对局模型
- GKG4／5 导入与包内卡组入库：保留显式确认，不自动选择模型、执行预设或覆盖用户设置；来自远程会话的卡组仍按会话隔离
- V4 资产维护：现有 V3 维护接口不能直接用于 V4。目前 V4 可通过匹配的 GKG4／5 更新，独立维护入口需要另行实现，不能由插件绕过 Link 的协议和坐标系兼容检查
- 诊断工具：读取小型状态和覆盖摘要，详细报告按需获取；不把完整诊断每个动作重复注入聊天，也不返回密钥、原始报文或其他会话卡组

管理工具应保留管理员权限和现有 revision 乐观锁。主智能体赛前编辑临时卡组仍受显式开关与当前会话限制，不因新增管理入口扩大其可见范围

## 后续第三批：观众席和独立评测

顺序为 Link 接通服务器观众席、建立只含公开数据的观察、加入无动作菜单时的异步评测，最后让插件增加加入观战／停止观战／读取建议工具

观众身份不得被临时映射成决斗者，不上传或读取某方私有卡组来补全场面，也不回复 CTOS_RESPONSE。评测任务与对局动作任务分开，采用节流、过期结果丢弃与外部开关；未校准的模型价值只显示为局面分数，不能称作胜率。额外预测头需先核对 PTH／ONNX 部署输出，不能只改插件提示词就宣称支持

新增能力优先采用 API v1 中的可选配置、独立端点与事件，并保留默认的玩家对局行为。若后续确需改变原有请求或隐私含义，再提出明确的 API 迁移方案

## 验证边界

3.3.16 已通过 Link 自身的场面重建、异步取消以及 PTH／ONNX TCP 连续决策测试。两个插件的“不强制同步升级”结论依据当前源码的数据流和未改变的 API 合同；不等同本批已完成真实 AstrBot／dsh 长局联调，也不等同已实现上述后续批次

联调时检查连接和版本、保留 hybrid 等原模式、在合法时点产生远程判断、游戏聊天不重复、结束原因和一次性摘要、过期决策不回流，以及两个会话之间的卡组不可互见。无需为单纯 Link 解析补丁反复重做所有这些场景
