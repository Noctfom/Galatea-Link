# YGOPro 观众席与公开场面评测

Link 3.5.0 支持加入 YGOPro 服务器的独立观众席，并复用「模型反馈」面板做 V4 旁路评测。它与参与对局的玩家席位分开，不需要卡组，不生成等待提交的决策

## 在 WebUI 中使用

1. 更新后重启整个 Link 服务进程，确认启动横幅或 `/api/v1/health` 中的版本为 `3.5.0` 或更高
2. 停止现有游戏会话，在「配置中心」填写 YGOPro 服务器和房间参数，将「入房身份」改为「观众席」并保存。卡组和先后攻选项会禁用，保留原设置供以后参与对局使用
3. 启动会话，等待服务器分配正式观众席。若服务器先分配临时玩家席，Link 会请求切换观众；日志和房间事件会区分「等待切换」与「观众席」
4. 需要模型评测时，先在模型仓库选好可用的 V4 PTH 或 ONNX，再在「模型反馈」开启「读取模型反馈」和「持续旁路评测」并保存。默认只读取反馈，旁路不会自动开启
5. 面板会标明「观众席 · 仅公开场面」和参照玩家。选择 Core Player 0 或 1 后保存，可以查看相对于该玩家的价值与模型实际提供的终局概率

参照使用游戏消息中的玩家编号，不保证对应客户端画面的左边、下方或先攻方。改变参照不会申请玩家席位，也不会增加可见信息。运行中切换会清空本次曲线、使旧计算结果失效并重新采样；停止状态保存只影响下次会话，已经保存的上局曲线仍保留原视角

不加载 V4 也可加入观众席读取公开观察，但没有模型评测。观众会话不调用 Link 本地 LLM 做动作决策，也不请求 AstrBot／dsh 提交游戏动作；原有游戏聊天发送接口仍可使用

## 可见范围与预测含义

- 双方手牌、主卡组、盖放身份和未公开额外身份保持未知，不读取本地卡组补全任一方构筑
- 双方基本分、数量、位置、公开表示、已收到的公开卡片信息和公开连锁上下文参与观察；隐藏身份在观察和模型编码入口再次清理
- 双方初始构筑未知，卡组画像与相关 FiLM 输入关闭；无法取得的原生双方决策历史继续掩蔽
- 没有合法动作菜单时只评测状态，不生成虚构候选或场面操作建议。公开提示不会让观众进入游戏响应流程
- V4 模型原本学习的是玩家可见状态，公开观战缺少更多信息；其结果是对不完整公开输入的参考，不能称作任一玩家完整信息下的预测，尚未做概率校准

PTH 可读取已有终局头。当前 Core 普通双输出 ONNX 只提供折扣价值，胜／平／负概率和预计剩余事件显示为空；支持可选终局输出的图才显示这些指标。不会把价值换算成胜率，也不会用一个玩家概率的补数代替另一个玩家独立评测

图表仍采用固定采样序号窗口，不代表等距游戏时间。模型执行、节流、超时和过期丢弃复用[模型反馈](MODEL_FEEDBACK.md)的同一实现

## 中途加入与服务器限制

优先在开局前加入允许观战的房间。是否允许中途加入由服务器决定，某些房间或服务器可能拒绝加入或切换观众，Link 不绕过这个规则

公开基线来自实际观众 `MSG_START`，或在已确认观众座位后由服务器提供的 Type162 场面重建。没有有效基线时保持等待，不把普通玩家 Start 解释为观众私有视角，也不根据聊天、旧会话或本地卡组猜测当前场面

Type162 可以恢复当前数量、位置和连锁，但不能恢复加入前的全部历史或初始构筑。若中途仅收到重建基线，`turn_count_origin=observed_since_join`，面板标注「加入后回合计数」，不声称是整局绝对回合数；卡片身份仍依赖后续实际查询

## 配置与共享接口

配置文件新增以下可选项，现有配置默认仍为参与对局

```yaml
server:
  role: spectator

decision:
  core_feedback_enabled: true
  core_feedback_passive_enabled: true
  core_feedback_spectator_player: 0
```

只把上述字段合并到现有配置即可，服务器地址、模型及其他设置沿用原有内容。`server.role` 仅接受 `duelist`／`spectator`，参照必须为整数 `0` 或 `1`

| 用途 | API v1 入口 |
| --- | --- |
| 检查能力 | `GET /api/v1/capabilities`：`online_observation.spectator_seat`、`model_feedback.spectator` |
| 持久保存下次会话身份 | `PATCH /api/v1/configuration`：`patch.server.role` |
| 远程临时会话身份 | `POST /api/v1/session/configure`：`server.role` |
| 启动／停止 | 原 `POST /api/v1/session/start`、`POST /api/v1/session/stop` |
| 开关与参照 | `PATCH /api/v1/controls`：`patch.intervention.core_feedback_spectator_player` 及原反馈开关 |
| 读取公开观察 | `GET /api/v1/observation`，`perspective.role=spectator`、`player_id=null`，另给 `reference_player_id` |
| 读取缓存评测 | `GET /api/v1/model-feedback`，`role=spectator`、`reference_player`、`spectator_confirmed`；点内 `visibility=spectator_public` |

持久配置和控制修改继续使用原有 `expected_revision` 检查。读取评测接口只返回缓存，不触发额外推理。上层观察中的 `self`／`opponent` 仅为展示参照分组，不能据此将观众视为某个决斗者

API 仍为 `galatea.link.api.v1`，现有 AstrBot／dsh 的普通决斗不必同步升级。插件若要提供「加入观战、切换参照、读取评测」专用工具，需要后续单独增加能力识别和原会话所有者检查，当前没有修改插件仓库

网络入席与广播边界参考上游 [YGOPro 协议常量](https://github.com/Fluorohydride/ygopro/blob/master/gframe/network.h)和[单局服务器处理](https://github.com/Fluorohydride/ygopro/blob/master/gframe/single_duel.cpp)。Link 使用独立在线投影，不修改 Core 模型协议

## 已验证与现场复核

受控 TCP 覆盖真实 PTH、修订 14／15 ONNX，临时玩家席转观众、观众 Start／仅重建基线、双方公开投影、参照切换、终局及中止清理。测试检查实际出站包只有玩家信息、加入和转观众请求，没有卡组上传、准备、开局、猜拳、计时确认或游戏响应。HTTP 覆盖鉴权、离线保存和重载、非法参照及无卡组观战；浏览器检查保存、浅深主题和公开范围提示

以上使用受控服务器与测试权重，还需要以下真实环境复核

1. 正常 V4 玩家对局重走这次崩溃前的卡片移动／效果选择流程，确认后续操作仍响应；不要求先做纯 LLM 测试
2. 由两名玩家进入真实房间，Link 以观众加入并确认席位；检查没有上传卡组或自动准备，观察可正常更新
3. 开启 V4 旁路后，确认新增反馈；切换参照并保存，确认旧曲线清空、实际观察仍没有双方私有手牌，普通 ONNX 仅价值也能工作
4. 若服务器允许中途观战，再测试加入已开始的对局；若没有公开基线，保留相关入席与消息类型日志，用于区分服务器限制和 Link 解析问题

反馈时提供运行版本、模型格式／修订、开局前或中途加入、主要操作及脱敏报错即可。不要公开服务器密码、服务令牌、LLM API Key 或他人私有卡组
