# V4 当前询问与逐链上下文兼容

适用于 Link 3.4.1，参考只读 Core 3.16.9 提交 `23d6fd0c1d57f38ab6736e7002acf9637f8d0fbf`。Core 软件版本用于记录来源；实际加载仍按模型协议、观测结构修订和资产身份选择

## 本次合同变化

模型协议仍为 **4**、检查点容器仍为 **3**。观测结构修订从 **14** 升为 **15**，输入由 **108** 项扩展为 **116** 项，追加 `current_context_mask/kind/code/location/chain/offset/subtype/value`，容量为 256 项事实

新增计算复用原有公开通知参数，没有增加、删除或改变已有学习参数的形状。它会改变有新事实时的策略与价值；保留权重不表示新语义已经学好或预测质量一定提升。当前事实与已完成动作历史分开，Link 继续屏蔽无法可靠取得的双方逐决策历史

## 新旧模型怎么用

| 制品 | Link 的行为 | 需要用户做什么 |
| --- | --- | --- |
| 修订 15 PTH | 使用 116 项输入和已有状态终局头 | 按原流程导入匹配资产并选择 |
| 已核对合同的修订 14 PTH | 保留全部原权重，在内存使用修订 15 计算及输入，提示预测可能变化 | 可以继续使用；不改写原文件 |
| 修订 15 ONNX | 严格使用图的 116 项输入 | 从当前 Core 导入对应图与同轮清单 |
| 修订 14 ONNX | 保留原图和 108 项签名，警告缺少当前上下文分支 | 可继续对局；需要新增观测时才从对应 PTH 重导出 |

旧 ONNX 不构造自己没有的新输入分支，新分支容量也不影响它。改变清单或哈希不能让旧图得到新计算路径。没有对应 PTH 时，Link 不负责恢复或重导出权重

模型仓库与运行状态增加 `runtime_protocol_schema_revision`、`observation_compatibility`，说明原制品修订、实际运行修订、输入数量及 `current_context_supported`。制品的 `protocol_schema_revision/hash` 保留原身份，资产内容演进仍沿用已有的词表前缀与语义坐标系合同

目前只接受已知的修订 14／15，未知结构、改变既有卡片编号、缺失权重或真实模型输入尺寸冲突仍不能当作普通元数据差异跳过。这些模型错误走原回退，不把辅助提示差异升级成服务器断线

## 在线事实来源

| 消息 | 新传导的信息 | 处理边界 |
| --- | --- | --- |
| Type2 / SELECTMSG(3) | 完整 32 位参数、当前提示类型及原投递玩家 | 不把卡密或其他参数强行解释成“代价／目标”用途 |
| Type2 其他已知子类型 | 已实际收到的事件、选项、宣言和卡名通知 | 按子类型区分投递角色，无链保留最近 16 项，链内保存至链结束 |
| 70／71 | 原始链号、建立及确认状态 | 不因结算弹栈重编号 |
| 72／73 | 最近开始处理的链号、正在处理与已处理标记 | 已处理链留到 Type74，处理完成不等于效果成功适用 |
| 75／76 | 指定链的发动无效与效果无效 | 两类状态分别存放，不传播为整条连锁全部无效 |
| 83 | 公开指示的公告位置、已知身份、当前可追踪位置 | 也可能来自 `HintSelection`，与查询的持久取对象关系独立 |
| 162 | 快照内的链来源 | 未携带的提示、对象、处理状态标为未知，不延用重建前缓存 |

Type2 的玩家字段不是通用行动者。1／2／3／5 投递给该玩家，4／6／7／8／9 投递给另一玩家，10／11 双方可见。普通对局只允许当前真实接收者的玩家投影，不因为本地加载了模型就取得另一座位的数据。3.5.0 的观众席另有公开投影，清除私有选择提示，不会借切换参照扩大可见范围

兼容窄提示和已识别的宽提示。未知子类型、非法投递角色或无法放入 32 位合同的宽参数只写脱敏结构警告，不构造模型事实、不清空正在等待的合法菜单，也不单独终止连接

## 生命周期与可见性

选择提示在下一有效询问消费，Retry 保留原用途。Type26 连续逐项选择可以延用提示，完成或离开流程才消费；新提示替换旧提示后，旧响应不会删除新用途。Link 在网络写入前暂存响应，写入失败或取消时撤回仍属于该次发送的暂存信息

无链的多条 Type83 累积为同一公开指示窗口，下一决策可以查看，Retry 延用，下一新决策或终局／回合／阶段切换清理。链内对象按原始链号分组

明确移动、交换、素材索引变化可以更新当前位置。洗牌、身份冲突或查询证明实例已消失时停止追踪，保留原公告及当时合法已知身份；旧槽位的新卡不会继承旧对象。单卡查询只校准实际刷新的槽位，不假设其他位置已经同步更新

LLM 的 `public_context.prompt_notifications`、`resolving_chain_number`、`recent_indicated_cards` 以及 `chain[].indicated_cards` 复用相同事实。隐藏身份按可见性掩码裁剪，卡名／卡文本只为合法已知卡加入目录。未知状态保持未知；LLM 展示列表有上限并声明截断。模型 256 项容量溢出会使该次模型推理走回退，不静默制造完整观测

## 图表与插件

[模型反馈](MODEL_FEEDBACK.md) 改用单调 `sample_id` 和固定长度采样窗口，新增 `series_id`、`total_samples` 是 API v1 的可选字段。读取接口不触发推理，旧客户端可以忽略新字段

LLM／AstrBot／dsh 继续使用相同决策身份和标准观察。当前两个插件会透传补齐字段，因此本批仅需升级并重启 Link，插件不必强制同步升级。没有在本批修改插件仓库，也没有取得真实插件长局验收结果

## 已做验证

- 修订 14 PTH 原文件摘要、全部参数逐项保持不变；空上下文前向一致，打开既有通知门控后新增事实确实进入计算
- 真实 ORT 执行 108／116 项签名图，旧图不受新分支容量影响；缺少可选终局头仍只显示价值
- 选择提示消费、Retry、新提示替换、逐项选撤、逐链状态、无链指示累积、洗牌与查询失联、隐藏身份和 Type162 清理
- 在内存执行 Core 实际状态更新与原始当前上下文编码方法，两个座位的八项新输入一致；原有查询和复杂提示对照扩展至当前 116 项合同
- 本机 TCP 连续三阶段决策覆盖新 PTH、新旧 ONNX，链上下文进入中间提示，重建后清除旧事实，不使用 RuleBot 替代该回归中的模型决策
- 浏览器核对固定坐标、无黑色填充、原地刷新、历史超容量滚动、主题、无概率降级与设置保存

这些是受控状态、轻量权重及模拟服务器验证，不等同真实训练权重的策略质量、胜率校准或所有服务器版本均已验收。本批没有发现需要另交 Core 修复的解析缺陷

## 建议一次性现场复核

1. 重启整个 Link 服务进程，确认版本 **3.5.0** 或更高；在模型仓库核对所选模型的原修订与运行修订。旧 ONNX 显示缺少新观测属于兼容提示，应仍可开局
2. 使用正常 V4 对局走一次多次选择和多链处理。在「LLM 观察」确认当前选择参数、当前处理链及公开指示对象会更新，Retry 不丢用途，阶段或连锁结束后不残留旧对象；保存操作简述及异常日志即可，无需先单独做纯 LLM 测试
3. 打开「模型反馈」，前 64 点横轴固定为 0～64，新点不挪动旧点；窗口满后滚动。切换 32／128 点及浅深主题，确认没有黑色覆盖。普通双输出 ONNX 的胜利概率仍为空，应查看折扣价值
